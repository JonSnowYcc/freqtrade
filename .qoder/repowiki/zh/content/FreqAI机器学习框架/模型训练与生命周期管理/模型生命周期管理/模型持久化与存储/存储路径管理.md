## 简介
FreqAI模型的存储路径结构设计旨在实现高效、有序的模型管理和数据组织。该系统通过基于identifier和时间戳的目录组织方式，确保每个模型实例都有唯一的标识和存储位置。这种设计不仅便于模型的版本控制和回溯，还支持多模型并行训练和预测，提高了系统的灵活性和可扩展性。

## 存储路径结构设计
FreqAI模型的存储路径结构设计遵循一种层次化的组织方式，以确保模型数据的有序存储和高效访问。核心设计原则是基于identifier和时间戳来组织目录结构。identifier是用户在配置文件中定义的唯一标识符，用于区分不同的模型实例。时间戳则记录了每次训练的具体时间，确保每次训练的模型都有独立的存储空间。

存储路径的根目录位于`user_data_dir/models/`，其中`user_data_dir`是用户数据目录，通常在配置文件中指定。在此根目录下，每个模型实例都有一个以其identifier命名的子目录。例如，如果identifier为`freqai_model_1`，则对应的目录路径为`user_data_dir/models/freqai_model_1`。这个目录包含了该模型实例的所有相关数据，包括训练好的模型文件、特征管道、标签管道、训练数据集等。

在每个模型实例目录下，进一步的子目录按照训练的时间戳进行组织。具体来说，每个训练周期会创建一个名为`sub-train-<pair>_<timestamp>`的子目录，其中`<pair>`是交易对的名称，`<timestamp>`是训练开始的时间戳。这种设计确保了每次训练的模型数据都能被独立保存，避免了不同训练周期之间的数据冲突。此外，通过时间戳的排序，可以轻松地追踪模型的训练历史和性能变化。

## full_path生成逻辑
full_path的生成逻辑是FreqAI模型存储路径管理的核心部分，它决定了模型数据的最终存储位置。full_path的生成过程主要依赖于`user_data_dir`和`identifier`两个关键参数。`user_data_dir`是用户数据目录，通常在配置文件中指定，而`identifier`是用户在配置文件中定义的唯一标识符，用于区分不同的模型实例。

full_path的生成逻辑在`IFreqaiModel`类的`set_full_path`方法中实现。该方法首先从配置文件中获取`user_data_dir`和`identifier`，然后将它们组合成一个完整的路径。具体实现如下：

```python
def set_full_path(self) -> None:
    """
    Creates and sets the full path for the identifier
    """
    self.full_path = Path(self.config["user_data_dir"] / "models" / f"{self.identifier}")
    self.full_path.mkdir(parents=True, exist_ok=True)
```

在这个方法中，`self.config["user_data_dir"]`获取用户数据目录，`"models"`是固定的子目录名，`f"{self.identifier}"`则是模型实例的唯一标识符。通过`Path`类的组合操作，最终生成了完整的路径`self.full_path`。`mkdir(parents=True, exist_ok=True)`确保了路径的创建，即使父目录不存在也会一并创建，并且如果目录已经存在则不会抛出异常。

## 子目录创建规则
子目录的创建规则是FreqAI模型存储路径管理的重要组成部分，它确保了每次训练的模型数据都能被独立保存。子目录的命名格式为`sub-train-<pair>_<timestamp>`，其中`<pair>`是交易对的名称，`<timestamp>`是训练开始的时间戳。这种命名规则不仅提供了清晰的语义信息，还便于通过时间戳对训练历史进行排序和管理。

子目录的创建过程在`FreqaiDataKitchen`类的`set_new_model_names`方法中实现。该方法接收交易对名称和时间戳作为参数，然后根据这些参数生成子目录的路径。具体实现如下：

```python
def set_new_model_names(self, pair: str, timestamp_id: int):
    coin, _ = pair.split("/")
    self.data_path = Path(self.full_path / f"sub-train-{pair.split('/')[0]}_{timestamp_id}")

    self.model_filename = f"cb_{coin.lower()}_{timestamp_id}"
```

在这个方法中，`pair.split('/')[0]`提取了交易对的基币名称，`timestamp_id`是训练开始的时间戳。通过将这些信息组合成字符串，生成了子目录的路径`self.data_path`。同时，该方法还设置了模型文件的名称`self.model_filename`，确保每个模型文件都有唯一的名称。

## 变量协同工作机制
在FreqAI模型的存储路径管理中，多个变量协同工作以实现唯一性标识和高效的数据管理。这些变量包括`data_path`、`model_filename`等，它们共同决定了模型数据的存储位置和文件命名。

`data_path`是模型数据的存储路径，它由`full_path`和子目录名称组合而成。`full_path`是模型实例的根目录，而子目录名称则包含了交易对和时间戳信息。通过这种方式，`data_path`确保了每次训练的模型数据都能被独立保存。

`model_filename`是模型文件的名称，它由交易对的基币名称和时间戳组合而成。具体实现如下：

```python
self.model_filename = f"cb_{coin.lower()}_{timestamp_id}"
```

在这个表达式中，`coin.lower()`将基币名称转换为小写，`timestamp_id`是训练开始的时间戳。通过这种方式，`model_filename`确保了每个模型文件都有唯一的名称，避免了文件名冲突。

此外，`FreqaiDataDrawer`类中的`save_data`方法负责将模型数据保存到指定的路径。该方法首先检查`data_path`是否存在，如果不存在则创建它。然后，将训练好的模型、特征管道、标签管道、训练数据集等保存到`data_path`目录下。具体实现如下：

```python
def save_data(self, model: Any, coin: str, dk: FreqaiDataKitchen) -> None:
    """
    Saves all data associated with a model for a single sub-train time range
    :param model: User trained model which can be reused for inferencing to generate
                  predictions
    """

    if not dk.data_path.is_dir():
        dk.data_path.mkdir(parents=True, exist_ok=True)

    save_path = Path(dk.data_path)

    # Save the trained model
    if self.model_type == "joblib":
        with (save_path / f"{dk.model_filename}_model.joblib").open("wb") as fp:
            cloudpickle.dump(model, fp)
    elif self.model_type == "keras":
        model.save(save_path / f"{dk.model_filename}_model.h5")
    elif self.model_type in ["stable_baselines3", "sb3_contrib", "pytorch"]:
        model.save(save_path / f"{dk.model_filename}_model.zip")

    dk.data["data_path"] = str(dk.data_path)
    dk.data["model_filename"] = str(dk.model_filename)
    dk.data["training_features_list"] = dk.training_features_list
    dk.data["label_list"] = dk.label_list
    # store the metadata
    with (save_path / f"{dk.model_filename}_{METADATA}.json").open("w") as fp:
        rapidjson.dump(dk.data, fp, default=self.np_encoder, number_mode=METADATA_NUMBER_MODE)

    # save the pipelines to pickle files
    with (save_path / f"{dk.model_filename}_{FEATURE_PIPELINE}.pkl").open("wb") as fp:
        cloudpickle.dump(dk.feature_pipeline, fp)

    with (save_path / f"{dk.model_filename}_{LABEL_PIPELINE}.pkl").open("wb") as fp:
        cloudpickle.dump(dk.label_pipeline, fp)

    # save the train data to file for post processing if desired
    dk.data_dictionary["train_features"].to_pickle(
        save_path / f"{dk.model_filename}_{TRAINDF}.pkl"
    )

    dk.data_dictionary["train_dates"].to_pickle(
        save_path / f"{dk.model_filename}_trained_dates_df.pkl"
    )

    self.model_dictionary[coin] = model
    self.pair_dict[coin]["model_filename"] = dk.model_filename
    self.pair_dict[coin]["data_path"] = str(dk.data_path)

    if coin not in self.meta_data_dictionary:
        self.meta_data_dictionary[coin] = {}
    self.meta_data_dictionary[coin][METADATA] = dk.data
    self.meta_data_dictionary[coin][FEATURE_PIPELINE] = dk.feature_pipeline
    self.meta_data_dictionary[coin][LABEL_PIPELINE] = dk.label_pipeline
    self.save_drawer_to_disk()

    return
```

在这个方法中，`save_path`是`data_path`的路径对象，用于保存各种模型数据。通过`cloudpickle.dump`和`rapidjson.dump`等方法，将模型、特征管道、标签管道、训练数据集等保存到指定的文件中。同时，`dk.data`字典中也记录了`data_path`和`model_filename`等信息，以便在后续的加载过程中使用。

## 训练数据集与训练日期命名约定
训练数据集和训练日期的文件命名约定是FreqAI模型存储路径管理的重要组成部分，它确保了数据文件的唯一性和可追溯性。训练数据集的文件名通常包含模型文件名和特定的后缀，如`_trained_df.pkl`，而训练日期的文件名则包含模型文件名和`_trained_dates_df.pkl`后缀。

具体实现如下：

```python
# save the train data to file for post processing if desired
dk.data_dictionary["train_features"].to_pickle(
    save_path / f"{dk.model_filename}_{TRAINDF}.pkl"
)

dk.data_dictionary["train_dates"].to_pickle(
    save_path / f"{dk.model_filename}_trained_dates_df.pkl"
)
```

在这个代码片段中，`dk.model_filename`是模型文件的名称，`TRAINDF`是一个常量，表示训练数据集的后缀。通过将`model_filename`和`TRAINDF`组合成文件名，生成了训练数据集的文件路径。同样，训练日期的文件名也是通过将`model_filename`和`_trained_dates_df.pkl`组合而成。

这种命名约定不仅确保了文件名的唯一性，还便于用户通过文件名快速识别文件内容。例如，`cb_btc_1633075200_trained_df.pkl`表示这是一个名为`cb_btc_1633075200`的模型的训练数据集文件，而`cb_btc_1633075200_trained_dates_df.pkl`则表示相应的训练日期文件。
