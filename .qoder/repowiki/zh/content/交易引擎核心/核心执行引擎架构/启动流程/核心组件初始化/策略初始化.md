## 策略加载机制

`StrategyResolver.load_strategy()` 方法负责加载并初始化指定的交易策略。该过程首先检查配置中是否设置了策略名称，若未设置则抛出异常。随后，通过 `_load_strategy` 方法搜索并加载策略模块。

策略文件的搜索路径包括用户数据目录下的策略子目录（`user_data_dir/strategies`），以及配置中指定的额外路径（`strategy_path`）。当启用递归搜索（`recursive_strategy_search`）时，会遍历用户策略目录下的所有子目录以查找策略文件。

支持 Base64 编码的策略加载。当策略名称包含冒号（`:`）时，系统会将其解析为 Base64 编码的策略内容，并在临时目录中创建对应的 Python 文件，然后将其加入搜索路径的首位，确保优先加载。

策略加载完成后，会调用 `ft_load_params_from_file()` 方法从同名 JSON 文件中加载超参数。接着，对一系列策略属性（如 `minimal_roi`、`stoploss`、`timeframe` 等）进行覆盖逻辑处理。覆盖优先级为：配置文件 > 策略代码中的默认值 > 方法中定义的默认值。例如，若配置文件中定义了 `stoploss`，则会覆盖策略代码中的值；若配置中未定义，则使用策略代码中的值；若两者均未定义，则使用方法中提供的默认值。

最后，对策略属性进行归一化处理，例如将 `minimal_roi` 的键转换为整数并排序，将 `stoploss` 转换为浮点数，并将 `max_open_trades` 为 -1 的情况转换为无穷大。

## 策略验证过程

策略加载和属性覆盖后，会进行一系列验证以确保策略的完整性和正确性。

首先，调用 `_strategy_sanity_validations` 进行基础验证，包括检查 `order_types` 和 `order_time_in_force` 字典是否包含所有必需的键（如 `entry`、`exit` 等）。同时，验证做空策略不能在现货（SPOT）交易模式下运行。

核心验证由 `validate_strategy` 方法完成。根据交易模式（`trading_mode`）的不同，验证规则有所区别：
- **非现货模式**（如期货）：强制要求实现 `populate_entry_trend` 和 `populate_exit_trend` 方法。同时，会检查并警告已弃用的设置（如 `sell_profit_only` 应使用 `exit_profit_only`），并禁止使用已废弃的方法（如 `check_buy_timeout`、`custom_sell`）。
- **现货模式**：要求实现 `populate_buy_trend` 或 `populate_entry_trend`，以及 `populate_sell_trend` 或 `populate_exit_trend`。同样会发出弃用设置的警告。

此外，还会检查策略接口版本。如果 `populate_indicators`、`populate_buy_trend` 或 `populate_sell_trend` 方法的参数数量为2（即缺少 `metadata` 参数），则判定为已废弃的 V1 接口，并抛出异常。

其他验证包括：检查 `custom_stoploss` 方法是否包含 `after_fill` 参数，并据此设置内部标志 `_ft_stop_uses_after_fill`；检查是否同时实现了 `adjust_order_price` 与 `adjust_entry_price`/`adjust_exit_price`，若同时存在则抛出异常，要求策略选择其中一种价格调整方式。

## 策略配置参数加载流程

策略配置参数的加载主要通过 `HyperStrategyMixin.ft_load_params_from_file()` 方法实现。该方法在策略初始化时被调用，优先于配置文件中的值。

其工作流程如下：首先，根据策略文件的路径（`__file__`）确定同名的 JSON 参数文件（如 `MyStrategy.py` 对应 `MyStrategy.json`）。如果该文件存在，则使用 `HyperoptTools.load_params()` 加载其内容。

加载后，会进行策略名称校验，确保参数文件中的 `strategy_name` 与当前加载的策略类名一致，防止加载错误的参数文件。如果校验失败，则抛出 `OperationalException`。

一旦参数文件被成功加载，其中的配置将被应用到策略实例上。例如，`params["roi"]` 会覆盖 `minimal_roi` 属性，`params["stoploss"]["stoploss"]` 会覆盖 `stoploss` 属性，`params["max_open_trades"]["max_open_trades"]` 会覆盖 `max_open_trades` 属性（并将 -1 转换为无穷大）。这些参数的加载确保了通过 Hyperopt 优化得到的最佳参数能够被正确应用。
