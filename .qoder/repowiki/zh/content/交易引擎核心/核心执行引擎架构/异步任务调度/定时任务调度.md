## 简介
本文档详细解释了基于 `schedule` 库实现的定时任务调度机制，重点分析每日24小时×2次（1分和31分）的资金费更新任务（`_funding_fee_times`）的配置逻辑。说明该轮询策略如何确保在不同交易所的资金费结算时间窗口内准确捕获费用变动。阐述 `Scheduler().every().day.at()` 语法的使用模式及其与主循环 `run_pending()` 的集成时机。结合代码示例说明任务注册与执行的生命周期管理。

## 资金费更新任务配置逻辑
在 `FreqtradeBot` 类的初始化方法中，当交易模式为期货（`TradingMode.FUTURES`）时，会配置一个定时任务来定期更新资金费。该任务通过 `Scheduler` 对象进行调度，具体配置如下：

```python
if self.trading_mode == TradingMode.FUTURES:
    def update():
        self.update_funding_fees()
        self.update_all_liquidation_prices()
        self.wallets.update()

    for time_slot in range(0, 24):
        for minutes in [1, 31]:
            t = str(time(time_slot, minutes, 2))
            self._schedule.every().day.at(t).do(update)
```

此配置确保每天24小时，每小时的第1分钟和第31分钟执行一次 `update` 函数，该函数负责更新资金费、清算价格和钱包信息。

## 轮询策略与交易所结算时间窗口
该轮询策略通过每小时两次的定时任务，确保在不同交易所的资金费结算时间窗口内准确捕获费用变动。由于不同交易所的资金费结算时间可能有所不同，这种高频的轮询策略可以最大限度地减少因时间差导致的费用计算误差。通过在每小时的第1分钟和第31分钟执行任务，可以覆盖大多数交易所的结算时间窗口，从而确保资金费的准确更新。

## Scheduler().every().day.at() 语法使用模式
`Scheduler().every().day.at()` 语法用于指定每天特定时间执行的任务。在 `FreqtradeBot` 类中，该语法被用来配置每小时的第1分钟和第31分钟执行任务。具体使用模式如下：

```python
self._schedule.every().day.at(t).do(update)
```

其中，`t` 是一个字符串，表示具体的时间点，格式为 `HH:MM:SS`。`do(update)` 指定了要执行的函数。该语法与主循环 `run_pending()` 集成，确保在每个时间点检查并执行待处理的任务。

## 任务注册与执行生命周期管理
任务的注册与执行生命周期管理通过 `Scheduler` 对象和主循环 `run_pending()` 实现。在 `FreqtradeBot` 类的 `process` 方法中，`run_pending()` 被调用以检查并执行所有待处理的任务。具体代码如下：

```python
def process(self) -> None:
    # ... 其他逻辑 ...
    self._schedule.run_pending()
    Trade.commit()
    self.rpc.process_msg_queue(self.dataprovider._msg_queue)
    self.last_process = datetime.now(UTC)
```

`run_pending()` 方法会检查所有已注册的任务，并在满足条件时执行相应的函数。这种机制确保了任务的及时执行，同时避免了任务的重复执行。
