## Hyperopt与HyperOptimizer协同机制

Hyperopt类作为主控制器，负责协调整个超参数优化流程。它通过实例化HyperOptimizer类来执行具体的优化任务，形成主从式协同架构。Hyperopt在初始化时创建HyperOptimizer实例，并在优化过程中调用其方法进行参数空间初始化、优化器生成和结果评估。

HyperOptimizer类作为工作进程的核心，被设计为可序列化的对象，能够被发送到多进程环境中执行。它封装了回测引擎、策略配置和优化逻辑，确保在并行执行时保持上下文一致性。这种分离设计使得Hyperopt可以专注于流程控制，而HyperOptimizer专注于具体的优化计算。

## 避免参数重复采样机制

Hyperopt通过_get_asked_points方法实现参数去重机制，确保不会对已评估的参数组合进行重复计算。该机制包含两个层次的检查：首先检查历史已完成的试验，然后检查当前批次中的重复项。

```mermaid
flowchart TD
Start([开始获取参数点]) --> TryAsk["尝试获取n个参数点"]
TryAsk --> CheckHistory["检查历史试验中是否已存在"]
CheckHistory --> |存在重复| Discard["丢弃重复参数"]
CheckHistory --> |无重复| CheckBatch["检查当前批次内重复"]
CheckBatch --> |存在重复| RemoveDup["移除批次内重复"]
CheckBatch --> |无重复| ValidateCount["验证数量是否足够"]
ValidateCount --> |不足| Retry["重试获取"]
ValidateCount --> |足够| Return["返回非重复参数点"]
Retry --> TryAsk
Return --> End([结束])
```

## 多进程并行评估实现

```mermaid

Parallel->>Worker2 : 分发参数并执行
Parallel->>WorkerN : 分发参数并执行
```

## 参数分配与回测流程

generate_optimizer方法展示了从参数分配到回测执行的完整流程。该方法首先根据参数字典更新策略配置，然后加载预处理的数据，执行回测并计算结果。

```mermaid
flowchart TD
Start([开始优化]) --> ApplyParams["应用参数到策略"]
ApplyParams --> LoadData["加载预处理数据"]
LoadData --> RunBacktest["执行回测"]
RunBacktest --> CalculateResults["计算结果指标"]
CalculateResults --> CheckTrades["检查交易数量"]
CheckTrades --> |交易数不足| AssignMaxLoss["分配MAX_LOSS"]
CheckTrades --> |交易数足够| CalculateLoss["计算损失函数"]
AssignMaxLoss --> ReturnResults["返回结果"]
CalculateLoss --> ReturnResults
ReturnResults --> End([结束])
```

## 损失计算与阈值作用

_loss计算中MAX_LOSS阈值用于处理交易数量不足的情况。当回测产生的交易数量少于配置的hyperopt_min_trades时，系统会直接返回MAX_LOSS作为损失值，从而避免优化"HODL"类策略。

```mermaid
flowchart LR
TradeCount["交易数量"] --> |< min_trades| AssignMaxLoss["分配MAX_LOSS=100000"]
TradeCount --> |>= min_trades| CalculateRealLoss["计算真实损失"]
AssignMaxLoss --> BadResult["标记为不良结果"]
CalculateRealLoss --> GoodResult["标记为有效结果"]
```
